Arranque y servicios con systemd

Secuencia de arranque cada etapa entrega el control a la siguiente

systemctl isolate default.target detiene los destinos que no necesita y activa únicamente los que ese destino requiere.

Pulse para encender: UEFI entrega a GRUB2.

Dependencias entre unidades Requires= obliga · Wants= Desea · After= ordena

Operaciones y su efecto exacto

OperaciónEfecto inmediatoEfecto al reiniciar
systemctl start sshdArranca el servicio ahoraNo arranca, salvo que esté habilitada
systemctl stop sshdDetiene el servicio ahoraArranca si estaba habilitada
systemctl enable sshdNo cambia el estado actualArranca automáticamente
systemctl disable sshdNo cambia el estado actualNo arranca automáticamente
systemctl restart sshdstop seguido de startIgual que habilitada o no

Comprobación interruptor enabled / disabled

Estado simulado de sshd.service: enabled · activo

Al reiniciar, systemd arrancará sshd automáticamente.

Chuleta de comandos

systemctl status sshd # estado, PID y últimas líneas systemctl is-enabled sshd # enabled, disabled, static, masked systemctl cat sshd # unidad y drop-ins aplicados systemctl list-units --type=target # destinos activos systemctl daemon-reload # relee unidades tras editar un .service systemctl set-default graphical.target # destino de arranque por defecto journalctl -u sshd -b --no-pager # registro de sshd de este arranque systemd-analyze blame # unidades activadas más lentas
